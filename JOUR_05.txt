1. OBJECTIF DU JOUR

3. MÉTHODES HTTP ET FORMULAIRES
--------------------------------------------------------------------------------
Affichage du formulaire de création :
    GET /articles/create

Soumission de création :
    POST /articles

Mise à jour :
    PUT /articles/{article}

Suppression :
    DELETE /articles/{article}

Pour un PUT ou DELETE depuis un formulaire HTML, Laravel utilise le spoof :
    <form method="POST" action="{{ route('articles.update', $article) }}">
        @csrf
        @method('PUT')
        ...
    </form>

Explication courte : HTML ne supporte pas naturellement PUT ou DELETE. Laravel
simule la méthode avec @method('PUT').

4. CSRF
--------------------------------------------------------------------------------
Tout formulaire qui modifie des données doit avoir @csrf. Sinon tu as uneerreur
de token manquant.

Pourquoi : Laravel protège les soumissions contre les attaques CSRF. Le token
est vérifié côté serveur.

5. VALIDATION
--------------------------------------------------------------------------------
Dans le contrôleur :
    $validated = $request->validate([
        'title'   => 'required|string|max:255',
        'content' => 'required|string',
        'author'  => 'required|string|max:255',
    ]);

Ce qu'il faut retenir :
- validate() arrête tout si ça échoue,
- les erreurs remontent dans $errors,
- old() est rempli automatiquement pour certaines valeurs,
- tu récupères les données sécurisées dans $validated.

Exemple complet :
    public function store(Request $request)
    {
        $validated = $request->validate([
            'title'   => 'required|string|max:255',
            'content' => 'required|string',
            'author'  => 'required|string|max:255',
        ]);

        Article::create($validated);

        return redirect()->route('articles.index')
            ->with('success', 'Article créé.');
    }

Astuce : with() passe un message via session pour l'afficher après le redirect.

6. AFFICHAGE DES ERREURS DANS BLADE
--------------------------------------------------------------------------------
Au niveau de la vue :
    @if ($errors->any())
        <ul>
            @foreach ($errors->all() as $error)
                <li>{{ $error }}</li>
            @endforeach
        </ul>
    @endif

Champ par champ :
    <input name="title" value="{{ old('title') }}">
    @error('title')
        <p class="error">{{ $message }}</p>
    @enderror

old('title') redonne la valeur saisie si la validation échoue, ce qui évite de
refaire le formulaire depuis zéro.

7. UPLOADS BASIQUES
--------------------------------------------------------------------------------
Formulaire avec multipart :
    <form method="POST" action="{{ route('articles.store') }}"
          enctype="multipart/form-data">
        @csrf
        <input type="file" name="image">
        <button type="submit">Créer</button>
    </form>

Validation :
    'image' => 'nullable|image|max:2048'

Stockage basique :
    if ($request->hasFile('image')) {
        $path = $request->file('image')->store('articles', 'public');
    }

Si tu exposes le dossier public, lance parfois :
    php artisan storage:link

Ne jamais stocker un fichier sans le valider.

8. ORGANISATION DU TRAITEMENT
--------------------------------------------------------------------------------
Ce qu'il faut faire :
- valider en premier,
- traiter ensuite,
- retourner un redirect ou une réponse claire.

Ce qu'il faut éviter :
- faire des actions en base avant la validation,
- mélanger validation et logique métier complexe au même endroit,
- rediriger ou afficher sans message clair.

Exemple court et lisible :
    public function store(StoreArticleRequest $request)
    {
        $article = Article::create($request->validated());

        return redirect()->route('articles.show', $article);
    }

Ici la validation est dans StoreArticleRequest, le contrôleur reste court.
